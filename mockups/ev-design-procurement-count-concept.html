#95 · Earned Value accepts only an XML update with its baseline

If the planner opens Earned Value with an XER or an XML exported without its baseline, the screen shows only this card (no numbers):
"Earned Value reads an XML update exported with its baseline" — why (P6 measures Planned Value against the project baseline, only the XML carries it) + the 4 steps in P6 (check the assigned baseline → File ▸ Export ▸ XML → tick "export baseline" → import here). Every other feature keeps working with that file.
Planned Value = every cost-loaded activity's baseline cost × the part of its baseline duration planned up to the data date, summed — as you described. Grain 09 Aug: 652,633,400.05.

#96 · #97 · Design / Engineering / Procurement — Planned % and Actual % by count of activities

Today these scopes carry no cost, so the tool weights each activity by its duration and uses its % complete — that is why it does not match your count in P6 (e.g. Phase I Design shows 98.53%, your count gives 68 ÷ 70 = 97.14%).
Proposed: any scope with no cost is measured by count of activities, exactly as you check it in P6. Cost-loaded scope (Construction) stays cost-weighted, as P6's Planned Value.
How each number is made (P6 filters, per WBS / per Sub-WBS code):
• Actual % = activities with Activity Status = Completed ÷ all activities of the scope
• Planned % = activities whose BL Project Finish ≤ data date ÷ all activities of the scope
• In Progress is shown in its own column (counted as not yet complete)
